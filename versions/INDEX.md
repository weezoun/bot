`NOTES.md` documents ONLY what changed since the previous one (not a
repeat of earlier history) — this file is the fast way to find which
version to open for a given question, without reading every NOTES.md
from the start. Each entry below links straight to that version's

## How to add the next version

1. Pick the next number — usually `v<N>.<M+1>` for a small/config-scale
   checkpoint, or `v<N+1>` for a larger one; ask the user if unsure which
   scale a change counts as.
2. `mkdir versions/v<new>/code`, `versions/v<new>/stats` and copy every
   live source file + a fresh `trade_history.db` snapshot into them.
3. Write `versions/v<new>/NOTES.md`: a "Previous version" link back, a
   "What changed since v<prev>" section (ONLY the delta), and a stats
   baseline table at save time.
4. Go back and edit the previous version's `NOTES.md`: add/update its
   "Next version" line to point at the new one, and if it's a `NOTES.md`
   that was still being appended to directly (like `v2` was, before this
   scheme existed), mark it FROZEN as of this point.
5. Add a row to this table.
